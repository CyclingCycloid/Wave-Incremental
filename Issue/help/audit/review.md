# 候选结构版审计记录

## 基线与改动范围

固定基线：`6523dfc7257ca29003eb6e429ea1b858ffc7ec70`。本目录只读取该 Git 对象；仓库根目录主代码由其他 agent 维护，本候选工具不会写入它。

1. 原 `game.js` 的完整逻辑先分入 25 个按功能命名的源码段。生成器保持它们的原始排列与共同词法作用域，因而自动化、重置、生产、离线及 UI 的调用顺序不因拆文件变化。
2. WI1 存档编解码搬至 `src/modules/save-codec.js`，输入为数据或存档文本，输出为文本或解析对象；不读取 `state`、DOM、时钟。
3. `clampLog`、`logAddLogs`、`logAddSigned`、`cmpGE`、`cmpLT` 搬至 `src/modules/log-math.js`，仅通过初始化参数读取 `NLOG`、`LOG_CAP`、`LOG_FALLBACK`。运算分支与固定基线逐项对应。
4. 预览存储搬至 `src/adapters/storage.js`，浏览器看到的实际键始终为 `waveIncremental_help_` 加原键。写入或删除失败会向原保存处理器抛出，不制造“已保存”假象。
5. `Issue/help/index.html` 只调整了四处本地资源相对路径；`break_infinity.js` 依然先于候选脚本加载。候选运行代码被单一闭包包裹，避免污染浏览器全局作用域。

审计员对当前文件的源码差分、初始化顺序、路径、存储覆盖与构建输入哈希进行了只读复核，未发现新增阻断问题。动态行为与性能结果见 `../tests/`。

## 保留的风险

- 其余大部分函数仍通过共同闭包互相引用；目录分类仅供导航，尚非严格的模块依赖层。部分 `rules` 文件仍会修改状态或操作界面。
- `state` 在载入、导入、切槽和重置时可整体替换。后续模块不能持有旧对象引用。
- 当前购买路径仍包含最多十万次的 `buyMaxLoop` 和若干百轮自动购买循环；同步离线模拟仍有约 800 步。这些是固定基线继承问题，本次没有把它们宣称为已修复。
- 当前候选固定在上述提交。主代码后续提交的玩法修复需单独同步、审计与差分；不能直接以最新工作区文件覆盖候选源码段。
- `file://` 下的持久化能力取决于浏览器对本地页面 `localStorage` 的支持。若浏览器拒绝写入，候选显示保存失败。

## 后续提取准则

下一批仅抽取纯价格数学函数，并将报价与扣款拆成两个 API。任何算法优化都应独立于结构搬迁记录，明确资源单位、级数上限、免费门槛、挑战条件及近似误差。离线分片也应独立处理，以便把性能变化和公式变化分开审查。
