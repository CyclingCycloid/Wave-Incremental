# Wave Incremental 候选结构版

这个目录是可运行、可回退的候选实现。仓库根目录的 `game.js`、`index.html`、`style.css` 和 `break_infinity.js` 不由本目录的工具修改。

## 当前交付范围

- 基线固定为 Git 提交 `6523dfc7257ca29003eb6e429ea1b858ffc7ec70`，不读取其他 agent 正在修改的工作区主代码。
- 原 `game.js` 先按原字节拆成 25 个功能源文件；随后将 WI1 编解码与 log 基础运算搬入有明确输入/输出的独立模块。`source-manifest.json` 同时记录原始源码和当前候选源码的哈希，便于逐步审查差异。
- `build.mjs` 按原顺序拼装源文件，生成本目录的 `game.js`。生成代码放入单个闭包，避免把 564 个顶层声明暴露给全局作用域。
- `index.html` 是独立预览页，依旧使用经典脚本。双击打开时无需开发服务器或运行构建命令；`break_infinity.js` 仍由根目录原文件提供。
- 候选版的所有 `localStorage` 键统一添加 `waveIncremental_help_` 前缀，包括主档、手动槽、槽名及最后打开的标签。写入被拒绝时保留原游戏的保存失败提示语义。
- 仅候选版暴露 `window.__waveHelpDebug`，供浏览器审计对照；正式主代码没有这个接口。

## 运行与构建

直接打开 `Issue/help/index.html`，或在仓库根目录启动静态服务器后访问 `/Issue/help/`。修改 `src/` 后运行：

```powershell
node Issue/help/build.mjs
```

构建脚本会核对 25 个分段及三个独立模块的 SHA-256；若任一源文件发生改动，它会拒绝重建，要求先审查差异并明确更新 manifest。`tools/extract-baseline.mjs` 仅用于从固定 Git 对象重新提取原始分段，会拒绝覆盖已经存在的候选源文件。

## 架构边界

当前版本是**安全的第一阶段拆分**：维护源码按 `core`、`rules`、`engine`、`services`、`ui`、`app` 分类，并已独立抽出存储适配、WI1 编解码和 log 基础运算。目录分类是导航索引，`rules` 下仍有状态修改和界面副作用。生成后的主体代码仍共享一个闭包中的原有词法绑定；它尚未把全部函数改造成显式 import/export 或显式 `GameContext`，因此不能声称已经消除了玩法层间的所有耦合。这样安排是为先建立可对照的运行基线，后续逐个模块提取时才能识别公式变化。

下一阶段的真实解耦顺序为：独立 log 数值库及资源读写 → 只计算不扣款的购买报价 → 状态操作/重置 → 在线与离线共用的推进核心 → 存档/时钟适配 → UI 读取层。每完成一层，都需由审计和浏览器差分结果确认，再更新候选版。

## 已继承而尚未修正的风险

本次仅改组织方式，**没有宣称修好原版性能问题**。候选版仍继承 `buyMaxLoop` 的最高十万次循环、SAU/SBU/SVPU 自动购买的百轮循环、同步离线模拟的约 800 步，以及原版各处价格边界问题。它们必须在独立的购买库和离线阶段处理，不能与纯搬迁混在同一差异里。现有风险清单见 `../Plans/AutoBuy.md` 与 `../Plans/Offline.md`。

## 预览存档

候选页不会自动读取正式游戏的 `waveIncremental_save` 或六个正式槽位。若要检查旧档兼容性，请先在正式版导出 TXT/文本，然后在候选页主动导入。候选页的硬重置也只作用于带 `waveIncremental_help_` 前缀的键。
