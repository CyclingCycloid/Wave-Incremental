## 执行约束

1. 原始 game.js、index.html、style.css 保留。实施时先把候选实现放进独立的 Review 目录，写明与原文件的差异，供审查后再决定是否接入游戏。
2. 修复既有公式的实现错误与改变设计规则要分开处理。任何改动都须说明原规则、预期行为、数值边界及对旧存档的影响。
3. 自动购买的热路径不得按可买等级循环、二分搜索或迭代求根；购买数量应由预生成的逆表或直接公式得到。整轮购买计算必须明显短于 100 ms 逻辑 tick。
4. 离线结算可按时间推进必要的事件，但不得在一个浏览器任务里同步跑完整段离线时间；每段须让出主线程。
5. 本次只新增审查文档，未更改游戏代码，也未对这些方案做运行验证。后续实际更新默认提交并推送；没有明确要求时不更改版本名称。

## 新增问题编号

- A01：免费升级按总价而非末项门槛计算，批量购买少买。
- A02：升级 1 跨频率软上限时批量价格段冻结；已超过 332 级时求和起点可能错误。
- A03：自动 SBU/SVPU 逐次调用购买函数，可能反复触发保存与 DOM 刷新。
- A04：通胀升级 2 与 SBU2 的价格函数存在随等级增长的循环。
- O01：离线模拟同步执行最多约 800 步，并叠加自动购买工作。
- O02：虚拟时钟从加载时刻向未来推进，旧时间戳在第一步就看见整段离开时间；结束后还需不完整的时间戳平移。
- O03：存档写入会推进 lastTick，后台生产 tick 若停滞，未结算时间可能被抹掉。
- O04：离线未执行在线 tick 内的 SVU1、SVU2 和部分自动化解锁逻辑。
- O05：粗步长下黑洞脉冲质量衰减和 VP 产出与短步长严重偏离。
