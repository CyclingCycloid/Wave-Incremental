# 离线结算修正方案

状态：修改前方案；未改游戏代码。主要位置：game.js 1550–1566、7530–7665、7817–7938。对应 S02、S05、N10、D05、O01–O05。

## 已确认的代码路径

1. 加载时 runOfflineSimulation 同步循环约 60–800 步；每一步执行完整生产和自动化。晚期自动购买还可能运行多轮购买或随等级增长的价格循环，故总耗时无法由 800 这个步数保证。
2. gameNow() 在离线期间等于 Date.now()+累计偏移，模拟从加载时刻向未来推进。旧存档时间戳在第一步已被当作经过整段离开时间；结束后靠字段列表把新时间戳平移回来。列表未覆盖 compStartReal、湮灭/卷缩历史的 at 等字段。
3. distortEnterAt 是 JS 全局变量而非存档字段；在膨胀挑战或包含膨胀规则的虚空中重开会失去进入时间。此问题也见 Bug 报告 S02。
4. 离线只调用 applyProduction 和 runAutomation，跳过在线 tick 的 SVU1 投入、SVU2 增长和部分自动化解锁。纯生产跨门槛后，余下离线时间可能仍按未解锁状态运行。
5. 保存函数会把 lastTick 更新为 Date.now()。若后台计时器的保存先于被节流的生产 tick 执行，未结算的时间有被标记为已结算的风险。
6. 黑洞脉冲目前以本步起始质量计算衰减率，长步长直接推到末值，再用末值计算整步 VP 产出。示例：lg(M)=1000、dt=36 秒时会直接钳到 0；若按当前声明的分段每秒速率连续推进，末值约为 26.3，差异显著。是否保留“离散 tick”规则仍需审查，不应无说明地改写在线机制。
7. offlineLogDiff 得到的是 log10(新值/旧值)，弹窗却把倍率显示成“+资源”。例如波速从 100 到 200，显示 +2，实际增加 100。

## 时间轴与存档修正

- 将 lastTick 的语义固定为“状态已结算到的现实时间”，只在在线逻辑 tick 或离线重放成功推进后更新（冻结态 tick 也属于已处理时间）；saveGame、导出和槽位保存只写现有时间戳，不代替逻辑推进。
- 排队时一次性捕获 endMs=Date.now()。若原始间隔超过 8 小时，只模拟最近 8 小时，startMs=endMs−8 小时；否则 startMs 为上次已结算时间。超出上限的早期时间不产资源，但旧冷却仍随现实时间自然到期。
- gameNow() 在离线期间返回绝对模拟时刻 startMs+已推进毫秒，在线仍返回 Date.now()。离线写入的事件时间戳天然属于现实时间轴，删除事后字段平移和特殊漏项风险。
- 把膨胀规则的进入时间持久化到 state。旧档若正处在膨胀规则中，以同一次进入时写入的 annStartReal 作为迁移候选；字段异常再保守回退，并记录迁移口径。

接口草案：

~~~js
let offlineNowMs = null;
function gameNow() {
  return offlineNowMs === null ? Date.now() : offlineNowMs;
}
// 离线开始：offlineNowMs = startMs
// 每步推进：offlineNowMs += dt * 1000
// 成功结束：state.lastTick = endMs；offlineNowMs = null
~~~

## 结算内容与计算量

- 提取在线 tick 中不依赖 DOM 的共同数值阶段，在线和离线按相同顺序调用：生产、自动湮灭、SVU1、SVU2、自动化解锁、自动购买及自动卷缩。离线继续不增加“真实游玩时长”统计；该规则已有注释，不能顺手改变。
- 成就分为会改变数值的门槛成就和依赖打开页面、鼠标/键盘操作的成就。前者在离线跨门槛时更新，后者不得因为重放而伪造。
- 自动购买调用 Review/AutoBuy 中的即时报价库，禁止在某一个离线步骤内按购买级数循环。离线工作拆成浏览器可让出主线程的小任务；每段处理时间目标不超过 4 ms，处理完显示进度，再调度下一段。单步本身也须被购买报价的固定成本约束，不能仅在外层加计时器。
- 不要求 8 小时离线在一个 100 ms tick 内全部完成；要求加载界面持续响应、进度可见，完成前游戏输入、普通 tick 与自动存档不并发修改同一状态。
- 隐藏标签页若出现超过 60 秒的未结算间隔，也走同一离线管道；必须在覆盖 lastTick 前捕获时长，避免现有 60 秒钳制吞掉其余时间。

## 长步长物理

脉冲质量的既有速率声明为：x=lg(M)>30 时 dx/dt=−(1+0.1x)，x≤30 时 dx/dt=−1。高段的固定系数解为 x(t)=(x0+10)exp(−0.1t)−10；到达 x=30 的时间为 10ln((x0+10)/40)，其余时间按低段线性下降并以 0 为下限。离线候选先只替换长步长推进，再审查是否统一在线路径。

VP 产出随脉冲质量变化，不能再用末质量的瞬时速率乘整个长步长。候选方案按高段/低段最多两个区间，用区间代表质量作保守积分近似；原有 VF 加成与 VP 软上限仍由同一价格/产出函数计算。吸积状态的质量获取还含频率与软上限，先保持原公式并单独评估长步长误差，不把简单幂律解析式强行套到完整公式上。

## 完成与失败的原子性

离线启动前保存原始状态快照；完整成功才提交并保存一次。异常时恢复快照和原 lastTick，报告失败，不把“已模拟一部分”冒充完整 8 小时，也不覆盖旧存档。浏览器在模拟中关闭时，旧存档仍可在下次载入时重试。

收益弹窗使用真实绝对差值：在 double 安全时直接新值减旧值；超大值以 logAddSigned(新值,+1,旧值,−1) 求增量。衰减才显示前后倍率。弹窗还需显示实际结算时长及自动重置次数，避免净资源被自动花掉后误认为没有离线进度。

## 审查场景

- 膨胀挑战中保存/刷新；自动湮灭、自动卷缩后立即刷新；历史记录时间不得落在未来。
- SVU1 投入、SVU2 增长、1e10/1e20 自动化解锁、纯生产解锁成就。
- 脉冲 lg(M)=1000 的 36 秒推进；同一起点的在线短步与离线长步，分别比较质量与 VP。
- 资源 0→正数、100→200、正数→下降及离线自动消费后的弹窗表述。
