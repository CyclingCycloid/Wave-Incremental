# 自动购买修正方案

状态：修改前方案；未改游戏代码。主要位置：game.js 1791–1817、6503–6588、6594–6793。

## 要解决的问题

- N01：通胀升级 2 的前段批量总价误用每级 ×10；普通阶乘段连只买一级也可能套用约 1.111 倍上界。
- A01：免费升级只免扣款，不免当级价格门槛；当前部分批量函数仍用累计总价判断数量。
- A02：升级 1 的软上限状态会随付费而变化，批量报价不能冻结该状态。起始等级已高于 332 时，现有分段求和可能把较早等级重复计费。
- A03：自动 SBU/SVPU 未传入 bulk=true，成功购买后可逐次保存和刷新。
- A04：通胀升级 2 和 SBU2 的价格计算含按当前等级增长的循环，离线重放会放大成本。

## 必须保留的语义

- 频率 F=U/(有效波长)^e；频率价格由 U 支付时，扣款须按有效波长的 e 次幂换算。
- 升级免费只取消扣款，不取消价格门槛；滞涨宇宙禁用该免费效果。
- 主要页先买升级 1 再买升级 2，声子页依次买 PG1/PG2/PG3，升级 3 后同 tick 回购；窄宇宙次数、冻结状态、升级依赖、重置副作用不变。
- 低数值单次购买继续使用原有 double 比较口径；批量路径使用 log 权威值。

## 函数库设计

实施候选放在 Review/AutoBuy/，原 game.js 不动。purchase-catalog.generated.js 存放开发时生成的价格分段、逆查表和近似系数；purchase-math.js 是不读写全局状态的报价库；purchase-adapter.js 负责快照、复核和一次性提交；game.candidate.js 展示接入差异。

~~~js
const q = PurchaseMath.quote({
  id: "up2", level: state.up2, balanceLog: FLog(),
  free: upgradesFree(), maxCount: autoBuyTimes("wave"),
  inflation: inDistort("inflation")
});
// q: { count, costLog, valid, priceRegime }
if (q.valid && q.count > 0) commitPurchaseOnce(q);
~~~

库内没有随可买等级增长的循环、二分搜索或迭代求根。购买时只代入当前资源、等级和模式，读取静态逆表或计算直接公式。当前余额不断变化，所以不能把最终购买数本身静态存储；预解算的是由余额得到购买数的逆关系。

### 等比段

首项价格 c、每级倍率 r>1、可用资源 B 时：

- 付费：k=floor(log_r(1+(r−1)B/c))。
- 免费：若 B<c 则 k=0；否则 k=1+floor(log_r(B/c))。

在 log 域求值并以剩余等级上限、安全整数上限裁剪。等比总价使用末项形式计算，不构造大数。候选等级仅作固定次数的末项及总价复核，复核失败取保守结果，不能以循环搜索修正。

### 阶乘段

普通升级 2 的第 99/100 级同价；通胀升级 2 在第 11/12 级换段。必须分别结算段内价格。低等级和换段附近由开发时生成的逆查表覆盖；高等级使用阶乘对数的显式 Lambert W 近似。SAU/SBU 中带阶乘的价格也按各自的线性项与阶乘项建立逆关系。不能把普通升级 2 高段的既有 lgamma10 口径悄悄改成另一种价格。

阶乘段价格每级至少增长到该段声明的最低倍率 r 后，可用末项给出总价上界：

~~~js
function sumUpperLog(lastPriceLog, count, minRatio) {
  if (count <= 0) return NLOG;
  const q = 1 / minRatio;
  return lastPriceLog +
    Math.log10((1 - Math.pow(q, count)) / (1 - q));
}
~~~

该式对单级精确，对多级保守；使用前必须先切开增长倍率不满足条件的边界。允许极靠近价格门槛时少买，不允许低估花费、超买或扣成负数。

### 升级 1 的动态软上限

以初始 F 计算高频段可花的金额，并用等比逆式直接取得仍高于 1e100 的级数；再判定至多一个跨界购买。跨界购买按购买前的高频价格计价。剩余余额用低频段公式直接报价。整次调用固定两段，不逐级模拟；免费时 F 不下降，只使用初始价格段。第 332/333 级另外按价格斜率分段，已在 333 级以上时从当前等级开始。

### 共享货币升级

SAU、SBU 共用 Sp，SVPU 使用 VP。报价库对每个固定升级种类至多调用一次，按现有大类顺序生成一个保守的整组计划；资源分配和旧版 100 轮购买的细微差异须在审查表中明示。不得用“每 tick 最多再试 24 次”等逐级追赶替代预解算。提交时先复核快照仍有效，再一次扣款、一次加级；自动路径不逐级存档或刷新 DOM。

## 安全与验收条件

- 对非有限 log、LOG_CAP 饱和、非法等级、安全整数溢出返回无购买；不得把 NaN 钳成零价后授予等级。
- 覆盖免费/付费、F=1e100、升级 1 的 332/333、升级 2 的 99/100 与通胀 11/12、PG3 小数等级上限、窄宇宙、冻结与升级 3 重置。
- 购买数与价格接近门槛时允许保守少买；不得超支、负余额、越级或改变原价格公式。
- 候选实现完成后才测量整轮自动化耗时；目标显著低于 100 ms tick，不能仅凭复杂度声称已达标。
